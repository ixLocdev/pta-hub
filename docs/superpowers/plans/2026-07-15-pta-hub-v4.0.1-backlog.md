**Files:** Modify `includes/class-multisite.php` (`sync_to_targets`, the copy loop)

Today the sync copies title/content/excerpt/terms only, so a Council entry restricted to certain roles (`ptk_visible_roles`) becomes UNRESTRICTED on school copies. Propagate the restriction + the category meta fields.

- [x] **Step 1: Copy a whitelist of meta after each copy is created/updated**

```php
                // entries must stay restricted on schools) + category meta.
                $sync_meta_keys = array(
                    'ptk_visible_roles',
                    'ptk_difficulty', 'ptk_time_estimate',
                    'ptk_event_date', 'ptk_location', 'ptk_budget',
                    'ptk_last_reviewed',
                    'ptk_resource_url', 'ptk_file_type',

                foreach ( $sync_meta_keys as $mk ) {
                    if ( isset( $source_meta[ $mk ] ) && '' !== $source_meta[ $mk ] && array() !== $source_meta[ $mk ] ) {
                        update_post_meta( $copy_id, $mk, $source_meta[ $mk ] );
                    } else {
                        delete_post_meta( $copy_id, $mk );
                    }
                }
```
IMPORTANT: read the source meta on the MAIN site BEFORE the `switch_to_blog` loop (the function is entered on the Council site, where `$post`/terms are already loaded up top). Build `$source_meta` there:

```php
        // (up top, alongside the existing $post / $cat_terms / $tag_terms reads)
```

Then inside the loop use `$source_meta[$mk]` (as shown). NEVER call `get_post_meta( $post_id, ... )` while switched to a subsite — it would read the subsite's DB, not the Council's.

### Task 4: #17 — Daily log-pruning cron

**Files:** Modify `includes/class-analytics.php` (owns `ptk_search_log`); it will also prune `ptk_click_log`. Pattern: `class-public-preview.php:61` (schedule) + its unschedule on deactivation.

- [x] **Step 1: Schedule a daily cron**
In `PTK_Analytics::init()`, add a cron hook + schedule-if-missing:
```php
        add_action( 'ptk_prune_logs', array( __CLASS__, 'prune_logs' ) );
        if ( ! wp_next_scheduled( 'ptk_prune_logs' ) ) {
            wp_schedule_event( time() + HOUR_IN_SECONDS, 'daily', 'ptk_prune_logs' );
        }
```

- [x] **Step 2: The prune method (>12 months, both tables)**
```php
    /**
     * Delete search/click log rows older than 12 months. Runs daily via cron —
     * these tables accept nopriv inserts and would otherwise grow unbounded.
     */
    public static function prune_logs() {
        global $wpdb;
        $cutoff       = gmdate( 'Y-m-d H:i:s', strtotime( '-12 months' ) );
        $search_table = $wpdb->prefix . 'ptk_search_log';
        $click_table  = $wpdb->prefix . 'ptk_click_log';
        $wpdb->query( $wpdb->prepare( "DELETE FROM {$search_table} WHERE searched_at < %s", $cutoff ) ); // phpcs:ignore WordPress.DB
        $wpdb->query( $wpdb->prepare( "DELETE FROM {$click_table} WHERE clicked_at < %s", $cutoff ) ); // phpcs:ignore WordPress.DB
    }
```
(Confirm the timestamp column names: `ptk_search_log.searched_at` and `ptk_click_log.clicked_at` — read the create-table methods to verify before finalizing.)

- [x] **Step 3: Unschedule on deactivation**
In `pta-knowledge-hub.php` `ptk_deactivate()`, add `wp_clear_scheduled_hook( 'ptk_prune_logs' );` alongside the existing `flush_rewrite_rules()`.
